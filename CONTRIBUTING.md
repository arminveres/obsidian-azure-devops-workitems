# Contributing

Thanks for taking an interest in this plugin. Issues and pull requests are welcome.

## Getting set up

```bash
npm install
npm run dev     # esbuild watch build
```

To try your build in a real vault, symlink or copy the repository into
`<your-vault>/.obsidian/plugins/azure-devops-workitems/` and enable the plugin under
_Settings → Community plugins_. `main.js` is generated by the build and is not committed.

You will need an Azure DevOps organization to test against. A personal access token with the
_Work items (read)_ scope is the quickest way to authenticate; never commit `data.json`, which is
where that token is stored.

## Before you open a pull request

```bash
npm run lint    # must report zero errors
npm run build   # type checks, then produces main.js
```

There is no automated test suite, so please describe what you tested manually — which view
(Reading, Live Preview), which authentication method, and whether you tried Azure DevOps Services,
Azure DevOps Server, or both.

## House style

- Tabs for indentation, double-quoted strings, semicolons.
- Comments explain *why*, not *what*. The code is deliberately sparse on comments.
- British spelling where the codebase already uses it (`normalise`, `colour`).
- Explicit return types on exported functions and public methods.

## Obsidian review rules

This plugin follows the community catalogue guidelines, and `npm run lint` enforces them through
`eslint-plugin-obsidianmd`. In particular:

- Build DOM with `createEl` / `createDiv` / `createSpan` / `createFragment`. Never assign
  `innerHTML`.
- Put styling in `styles.css` and toggle classes; avoid `!important`.
- Register listeners, intervals and editor extensions through the plugin so they are torn down
  automatically.
- Node APIs are desktop only. Guard them with `Platform.isDesktop` and load them lazily, and do not
  rely on Node's ambient types — see `src/auth/cliProvider.ts`.
- All HTTP goes through Obsidian's `requestUrl`, never `fetch`.

## Reporting a security issue

Please do not open a public issue for anything involving credentials. Use GitHub's private
[security advisory](https://github.com/fvandillen/obsidian-azure-devops-workitems/security/advisories/new)
form instead.
